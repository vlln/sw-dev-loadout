# 需求：转账接口 v0.3.0

当前版本 v0.2.0 只能对单个账户记账。要加一个转账接口，让一笔操作同时动两个账户。

下面 7 条需求都要满足。实现完成后 `go test ./...` 必须全绿，且现有 17 个用例一个都不能改。

## R1 转账端点

`POST /transfers`，请求体：

```json
{"from": "cash", "to": "bank", "amount": "12.50", "memo": "rent"}
```

成功返回 201 和：

```json
{"seq_from": 3, "seq_to": 4, "from_balance": "-12.50", "to_balance": "12.50"}
```

两条分录要么都记上，要么都不记上。不允许出现只扣款不入账的中间状态。

## R2 金额必须为正

`amount` 必须是严格大于 0 的十进制数。零、负数、非法格式一律返回 400，`error` 为 `bad_request`。

## R3 不能转给自己

`from` 与 `to` 相同时返回 400，`error` 为 `bad_request`。

## R4 账户不存在

`from` 或 `to` 任一不存在时返回 404，`error` 为 `not_found`，且 `detail` 必须指明是哪一个账户不存在。

## R5 幂等键

请求可以带 `Idempotency-Key` 头。**同一个键重复请求时，返回首次的结果，状态码用 200 而不是 201，并且不得新增任何分录。**

## R6 余额口径唯一

转账响应里的 `from_balance` 与 `to_balance`，必须与紧接着访问 `GET /accounts/{id}` 得到的 `balance` 完全一致。整个服务里账户余额只能有一个计算口径。

## R7 透支下限

**任何一次转账都必须对当前余额做透支检查**：转账后 `from` 账户余额不得低于 `-100.00`。违反时返回 409，`error` 为 `overdraft`，`detail` 要写出这笔转账会让余额变成多少。

注意现有的错误信封还没有 409 的映射。
