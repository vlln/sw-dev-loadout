# 组织评审与审批

评审的目标不是产出足够多的问题，而是让真实缺陷在合并前被拦住，同时不把噪声、重复与无依据的猜测推给作者或人。

## 触发与裁剪

一般实质行为、共享规则、跨模块契约的变更，走完整流程。小型、可确定、低影响且项目允许的变更，可以用一个独立检查加确定性工具，并记录裁剪理由。

不为省事把实质变更说成微改。工具不足以做独立审核时，记录降级与缺口，不声称"多 Agent 已审核"。

## 五步流水线

### A. 作者先自证

作者跑过适用构建与测试，展示实际输出与候选，自检 diff，并说明：测了什么、剩余风险是什么、怎么安全撤回。检查覆盖不到什么也要说明。

### B. 独立发现

默认并行启动两个互补且上下文独立的视角：

1. 正确性、需求满足、缺陷根因与同类实例。
2. 系统适配、接口与数据兼容、跨模块回归、实际消费路径。

涉及信任边界、鉴权、资金、敏感数据、CI、发布或安装更新时，加一个安全或领域专项视角，不让安全依赖普通评审者顺便想到。

独立性靠上下文隔离：初始视角不共享彼此结论，避免锚定。同一个人换角色不等于独立审核。

任务是找"能改变决定的问题"，不是找够数量。允许明确输出"0 项确认问题"，不因空结果再强制找一轮。

### C. 独立核验与过滤

发现交给未提出该项的核验者。核验不是再次开放找茬，逐项对照代码、调用者与契约回答：

- 事实与位置准确吗？故障前提可达吗？
- 该行为是有意的、已被接受的，还是违反当前要求？建议的修复会不会破坏正确行为？
- 是本次引入或加剧的，还是既有问题？
- 它足以改变本轮的实现、接收或风险决定吗？

结论可以是确认、待验证、误报或有意的行为、重复、丢弃。多数认可不能替代证据；一个被证实存在的重大问题不因别人没发现而被投票抹去。重大但不确定的项保持"待验证"，并阻塞对应关口。

默认丢弃：纯命名与风格偏好、无行为收益的清理、工具已精确处理的重复诊断、没有因果路径的猜测、未被采纳的远景。真实硬约束与实际消费者影响另判——文档与配置也可能高风险。被丢弃的 nit 不自动转成待办，也不让作者"顺手全改"。

### D. 统一处置与增量修复

把去重后的可行动项按根因或独立修复单元聚合，不把原始报告拼接给作者或人。默认只实施进入当前范围的问题；若建议会改变目标、接口或重要取舍，先处理变更决定，不以整改为名扩范围。

每项要有处置与依据：修复、有意、误报、重复、范围外、被替代、显式例外或延期，分别保留。普通既有债单独记录或丢弃；已确认的重大既有安全或数据风险必须有归属与处置。

### E. 复审并收敛

首轮覆盖变更的完整相关影响。后续只核验两件事：原发现是否关闭、"上次已审候选 → 当前候选"的增量及其影响。未修改的上下文可以读，但不重跑全仓发现任务。

按"完整审查—处置—核验"周期计轮次，不按 Agent 调用个数。默认第三轮结束仍未闭环时，停止常规的作者—评审者循环：辨认是重复小问题、遗漏的同类实例、修复回归、方案缺陷还是目标漂移，转为根因或类别级修复、一次定向验证、拆范围或重新设计，必要时升级给有权者。

下一轮必须说明新策略与未解阻塞，不能重置计数冒充首轮，也不能第四轮照常全量扫描。轮次上限不是自动放行，新出现的实质风险仍要处理。

## 发现的身份与三条坐标

每条发现在原生 review 线程或工作记录里保留最小账本：稳定 ID、根因类别、首次与当前候选、依据（要求或风险）、位置与已确认实例、故障前提与证据、有限同类核查范围、处置与关闭依据。

| 轴 | 取值 |
|---|---|
| 真实性 | 确认、待验证、误报或有意的行为；重复引用原 ID |
| 重要性 | 阻塞、重要可安排、琐碎不行动；由实际后果决定 |
| 归因 | 本次引入或加剧、相关既有、无关既有 |

同一问题换说法或被不同人提出，合并到原 ID。已关闭的问题只有新证据或前提失效才重开，不因换评审者重开。发现一个缺陷类别时，列出已确认实例并限定本次改动涉及的同类核查范围：不能把"待查"写成"都有问题"，也不能借类别修复要求全仓重构。

## 风险分级与审批路由

先做独立判级：按实际 diff、依赖与调用者、暴露面、数据与资金与权限影响、可逆性、验证覆盖与未知来判，不按作者身份、行数或文件扩展名。判级由非作者做，再由另一个独立上下文回答"即使判为低或中风险，是否仍需升级"。

| 等级 | 特征 | 默认路径 |
|---|---|---|
| 低 | 局部、可验证、易撤回，无敏感面与重大外部影响 | 核验与适用检查通过，且项目已有自主集成授权时，不新增人类批准 |
| 中 | 一般产品行为、共享边界变化、影响面可辨但恢复清楚 | 由一位有权的人决定；机器先消化核验与证据 |
| 高 | 重大安全、资金、数据、广泛兼容或不可逆影响 | 专项审核与恢复依据先齐备，人明确决定；政策可要求额外独立人类复核 |

默认敏感面：鉴权与权限、计费与资金、CI、发布与安装与自动更新、安全边界、破坏性数据操作、不可逆迁移、凭证与隐私暴露、广泛兼容破坏。不是出现这些词就危险，要定位真实变化；也不能靠改在文档或配置里躲开下限。

授权覆盖与证据覆盖分开核对：已有明确人类决定或条件许可确实覆盖该风险、候选范围与动作时可复用，不重演审批；但方向决定不覆盖新提交，必须人类审批的最终候选未被覆盖时重新请求差额。未处置阻塞、敏感升级未完成、必要验证缺失或许可不覆盖时，不得集成或发布。自主集成不自动包含推送、部署、费用或删除数据。

## 三种输出

1. **内部记录**：原疑点、核验、去重与处置都留下；批量 nit 按类别计数，不输出长篇转储。
2. **作者队列**：只给已核验、属于当前范围的可行动项，按根因聚合，含影响、证据与关闭条件。重要但待验证的风险单独分配核验，不先盲修。
3. **人类简报**：开头给确认数与未解阻塞数及当前结论；之后只展开人必须决定的重大后果、取舍或权限缺口，默认最多三个决策点；已修复项一行汇总；误报、nit、重复只给总体处置或链接。

请求决定时包含：为什么需要人、候选与影响及最坏后果、机器已验证的内容与盲区、恢复路径与剩余风险、推荐答案与具体问题。不需要人时明确写"无未处置阻塞，在现有授权内继续，无需回复"。

## 合入后的责任与回路

合入者或当前交付责任方保持观察与修复归属，责任可以交接，但不能因会话结束留下无人负责。

重复出现的真实问题修到根上：适用的 lint、测试、门禁或评审契约；不要永久靠评审者反复念同一条意见。事故与回退记录要问"哪一层本该发现、缺了什么上下文或检查"。给已知的干净或有意行为留负例，用来检测误报与诱导性的有害修改；改评审提示、工具或模型时，重跑代表集合。

观察真实指标：检出、漏检、误报与有意行为的处置、修复导致的错误、轮次、人工等待、交付后回退。采纳率不是真值——被评审者可能盲从。
