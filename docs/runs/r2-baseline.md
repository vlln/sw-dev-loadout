# tally：`--json` 与 stdin 的实施计划

目标仓库：`/Users/vlln/Project/dsh-plugins/.sw-dev-experiment/round2/repo/`（快照，无 `.git`）
需求来源：同目录 `FEATURE.md`（4 条要求）
本文只定顺序、验收、证据与落地；不含实现代码。

## 0. 现状基线（实测，非推测）

以下全部由 `node /…/repo/src/cli.mjs …` 在临时目录实测得到（fixture 与探针命令留在计划评审记录里，不进仓库）。

| 可观察行为 | 当前值 | 备注 |
|---|---|---|
| 人类可读格式 | `` `${ext.padEnd(w)}  ${lines}\n` ``，`w` = 最长 ext 长度 | 两空格分隔 |
| 排序 | 行数降序；**同分按首次出现顺序**（`t1.aa t2.bb` 与反序输出顺序不同） | 隐式契约，现有测试未覆盖 |
| 行数规则 | `text.split('\n').length`：末尾有换行则 +1；空文件 = 1 行；`a\r\nb\r\n` 与 `a\nb\n` 同为 3 | 见 `test/count.test.mjs` 断言 |
| 扩展名提取 | `path.slice(path.lastIndexOf('.'))`；`dir.v2/plain` → `.v2/plain` | 既有缺陷，本轮不动 |
| 二进制跳过 | 仅按**路径后缀** `png\|jpg\|gif\|zip\|pdf`，不读内容 | 不认 `jpeg/webp/exe` |
| 退出码 | 0 成功；2 无参数（usage 到 stderr）；1 未捕获异常（`ENOENT`/`EISDIR`/`EACCES`，带完整栈） | 错误文本即栈，不可读 |
| 全部输入被跳过 | 退出 0，stdout 空 | `Math.max()` 得 `-Infinity`，不崩 |
| `--json`、`-` | 视作路径 → `ENOENT` 栈，退出 1 | 尚未存在 |
| 工程设施 | 1 条测试、无 CI、无 CHANGELOG、无 docs、`npm pack` 含 `FEATURE.md` 与 `test/` | 实测 `git status` = fatal: not a git repository |

由此得到三条硬约束，后文所有取舍都从它们推出：

1. **人类可读表的字节是公开契约**（`FEATURE.md` 明确"必须保持不变"），而它当前只被 1 条测试部分覆盖、且同分顺序与空结果两种情形完全没有测试。
2. **只做加法**：新增行为不得改变任何现有成功路径的输出。
3. **错误文本可以改善，但退出码是脚本会分支的接口**——改动必须显式记录，不能顺手。

非目标（本轮明确不做，避免范围膨胀）：改计数规则、改排序、修扩展名提取缺陷、扩二进制后缀清单、对文件路径做内容嗅探、加 `files` 字段、改版本之外的发布动作。

## 1. 实施步骤

单 PR，8 个依次提交的步骤（S0–S7）；每步给出**退出条件**（可观察，前置步骤不满足不进入下一步）。

| # | 步骤 | 做什么 | 为什么在这个位置 | 退出条件 |
|---|---|---|---|---|
| S0 | 冻结基线证据 | 用**改动前**的代码对固定 fixture 集录 stdout 原始字节、退出码、stderr 首行，产物落到测试 fixture（提交进 PR），不留在 PR 描述里 | 事后无法补录；这是"人类输出不变"唯一的可信依据 | fixture 与 golden 记录已提交；`node --test` 绿；S2/S3/S5 每一步之后对 golden 的 `diff` 为空 |
| S1 | 定契约 | 把 §5 的 D1–D5 落成一页契约（JSON 形状、退出码表、stdin 标签、空输入边界、`--`/未知选项），每个待定点同时写下被否的备选 | 公共序列化格式与退出码一旦发布，改动成本远高于书写成本；先定后写，代码阶段不再讨论 | 契约文档里每个待定点有确定取值 + 至少一行备选与否决理由 |
| S2 | 抽出纯函数缝 | 把"计数"（唯一一处行数规则）与"合并/排序"从 `count.mjs` 提成可被文件与文本共用的函数；`cli.mjs` 只剩 argv 解析 + 渲染 | stdin 与文件必须共用同一套计数与排序，否则 JSON 与人类输出必然漂移（AC3 会抓） | S0 的 golden `diff` 为空；现有测试不改断言即通过 |
| S3 | 错误与退出码收口 | `ENOENT`/`EISDIR`/`EACCES` → 一行可读消息（含出错路径）+ 稳定退出码 + 无栈；无参数保持退出 2；未知选项退出 2；支持 `--` 终止选项解析 | 这是**唯一改动既有失败路径**的一步，把兼容风险放在最前面暴露；后续两步在它之上都是纯增量，且空 stdin 报错要复用这套机制 | AC7–AC12 全绿；S0 golden 仍为空 diff |
| S4 | stdin | 路径为 `-` 时读全部 stdin，走 S2 的同一计数函数，标签 `(stdin)`；重复 `-` 报错；空 stdin 走 S3 的用法错误 | 依赖 S2（共用计数）与 S3（错误机制），故在其后 | AC4、AC5、AC8 全绿 |
| S5 | `--json` | 新增渲染分支，数据源与人类渲染共享同一 rows；空结果也输出合法 JSON；诊断只走 stderr | 最纯粹的增量放最后：此时文件与 stdin 两条数据通路都已就位，一次对两条通路做交叉校验 | AC2、AC3、AC11 全绿；S0 golden 仍为空 diff |
| S6 | 文档 | README 增补 `--json`、`-`、退出码表、JSON 形状、行数规则；`usage:` 字符串提到 `--json` 与 `-` | 与代码同 diff（文档与实现漂移是最常见的返工来源）；`usage` 变更必须与 golden 的"仅表格冻结"约定一致 | AC14；`usage` 字符串的测试断言按"包含"而非"逐字节" |
| S7 | 打包冒烟 + PR 文本 | `npm pack` → 临时目录安装 tarball → 用 `node_modules/.bin/tally` 复跑 AC1/AC2；写 PR 描述（动机、接口/行为变更、证据） | 源码树绿不等于消费者拿到的产物绿；这是唯一覆盖"真实交付对象"的检查 | AC15；PR 描述里的命令与输出全部是真正跑过的 |

提交粒度：S0 的 golden 单独一个提交（评审者可以先只看基线），S1 文档一个，S2–S6 各自一个。

## 3. 验证计划

分层，每层**唯一归属执行点**，同一提交不重复跑。

| 层 | 命令 | 覆盖 | 为什么是这层 |
|---|---|---|---|
| L1 纯函数单测 | `node --test test/count.test.mjs` | 行数规则（空文本/无尾换行/有尾换行/CRLF）、扩展名→标签、合并后排序与同分顺序、二进制跳过 | 纯逻辑，无需进程，最快给出"契约成立"的信号 |
| L2 CLI 契约 | `node --test test/cli.test.mjs`（`spawnSync` 真 bin，`input` 喂 stdin） | AC2、AC4–AC12（退出码、流分离、错误文本） | 退出码/stdout 纯净性/错误文本都是**进程级**契约，`import` 模块拿不到；且必须走真入口（`bin` 指向的同一个文件），不然加载器层面的问题不会被发现 |
| L3 golden 重放 | 同一 L2 文件内的期望文件，**只读** | AC1、S2/S3 的无行为变更证明 | 录一次真数据、之后确定性重放；期望输出只由 fixture 产生，测试绝不写入期望 |
| L4 属性/矩阵交叉校验 | `node --test` 内生成 `{空, 无尾换行, 有尾换行, CRLF} × {文件, stdin}` 矩阵 | AC3 | 两条渲染路径共享数据源这件事，只有矩阵级交叉校验能守住；单点样例过不了"某天有人给 JSON 分支单独排序" |
| L5 打包冒烟 | `npm pack` → 临时目录 `npm i ./tally-*.tgz` → `./node_modules/.bin/tally …` | AC15 | 消费者拿到的是 tarball 不是工作树；`bin` 路径与文件清单的错只有在安装后才会暴露 |
| L6 手动一次性 | 交互终端执行 `tally -`（期望立即报错而非挂起）；真 shell 里 `tally --json … \| jq .` | TTY 分支、真实管道 | 无依赖下无法自动化 pty；这条分支的证据形态是"命令 + 终端输出"，写进 PR |

改动面 → 证据映射（评审时按这张表核对，而不是"全跑一遍"）：

| 改动触达 | 跑什么 |
|---|---|
| `count.mjs` 计数/排序/跳过 | L1 + L3 |
| `cli.mjs` 解析、渲染、退出码 | L2 + L4 |
| stdin 读取路径 | L2（AC4/AC5/AC8）+ L6 |
| `package.json`（仅版本号） | L5 |
| README / usage 文本 | diff 评审 + AC11（stdout 纯净性） |

为什么这些够：

- 新契约的每一条（形状、退出码、流分离、stdin 语义）都有**进程级**断言；不是靠模块单测推断。
- "输出不变"由真实基线字节守护，而不是靠人眼比对；且 S2/S3 各跑一次 `diff`，行为漂移在提交粒度上被定位。
- 两条渲染路径的一致性有矩阵级交叉校验，覆盖了最容易腐化的那类退化。
- 交付对象（tarball）单独冒烟，源码绿不替代。

盲区（必须在 PR 里写明，不能假装覆盖）：

- **无 CI**：证据只存在于本地运行，PR 描述是唯一载体；没有平台矩阵。
- **Windows 未验证**：`/dev/stdin` 不可移植（实现必须用文件描述符方式读 stdin）；仅声明"不破坏既有路径行为"。
- **TTY 分支无自动证据**：只有 L6 的一次性人工记录。
- **stderr 断言受环境噪声影响**：本机 `NODE_USE_ENV_PROXY=1` 会让每个 node 进程先打一行 `UNDICI-EHPA` 警告，测试断言必须用"包含"匹配并显式排除栈帧特征（`/^\s+at /m`），不能用"stderr 为空"。
- **没有真实消费者**：没有已知的下游脚本样本，D1 的形状选错只能在发布后由反馈暴露。
- **覆盖率不作门禁**：`node --test --experimental-test-coverage`（当前 100% 行 / 75% 分支）只作参考数字，不设阈值——本项目没有 CI 去执行阈值。

门禁自证（轻量版）：提交前在本地做一次**临时退化**（例如把 JSON 分支改成单独排序、把计数函数的末尾换行规则改掉），确认 AC1/AC3 确实变红，然后还原。只记录"哪条断言红了"，不提交退化代码。

## 4. 落地安排

**前提事实**：该目录不是 git 仓库（实测 `git status` → fatal）。落地前必须先确定目标仓库、远端与分支基线；在此之前任何"提交/PR"动作都没有落点。

| 项 | 内容 |
|---|---|
| PR-1（本轮唯一） | 性质 `feature`；范围 S0–S7；风险 **medium** |
| PR-2（后续，本轮不做） | 性质 `bug-fix`：扩展名提取缺陷（`dir.v2/plain`、隐藏文件）+ 二进制后缀清单扩展。**它会改变现有计数**，因此必须独立成 PR、独立决定，不夹带 |
| 发布 | `0.3.0 → 0.4.0`（加法式新增 flag，SemVer minor）随 PR-1；**打 tag / `npm publish` 不在本轮授权内**，需针对该动作单独批准 |
| 记录 | 契约与取舍随 PR-1 提交（形态见 §5 D6） |

风险与缓解：

| 风险 | 影响 | 缓解 | 观察点 |
|---|---|---|---|
| 人类输出漂移 | 解析该表的脚本静默出错（最坏：无报错但数字错） | AC1 golden + AC3 交叉 + S2/S3 提交级 `diff` | PR 评审看 golden 文件本身 |
| 退出码语义变化（未知选项 1→2；空 stdin 新增 2） | 现有 `if [ $? -eq 1 ]` 类脚本分支失效 | 变化只发生在**原本就失败**的路径；README 与契约文档明示；PR 描述单列"行为变更" | 发布后 issue |
| JSON 形状选错 | 消费者返工，或需要 `--json=v2` 之类的补丁 | S1 先定 + 记录被否备选；形状保持最小（不预置版本字段） | 首个真实消费者 |
| stdin 在无输入环境挂起 | CI/脚本卡死 | TTY 检测 + 立即报错；读 stdin 一次即尽 | L6 |
| 打包漏文件 | 安装后 `bin` 不可执行 | 本轮不动 `files`；AC15 看守 | L5 |
| 范围膨胀（顺手修扩展名/二进制清单） | PR 混装，无法单独回滚与归因 | 非目标清单 + PR-2 承接 | 评审 |

提交纪律：一个文件同一时间一个写者；显式路径 `git add`（**不用 `git add -A`**）；提交前核对暂存清单只含本次改动；不 push、不合并、不打 tag、不发布，除非逐项获批。

批准路径：

1. **合并**：仓库 owner 一人（medium：一般产品行为变化 + 公共契约，恢复路径清楚——单 PR revert，无迁移、无持久化格式）。
2. **契约签字**（D1/D2/D3）：这三个决定改变的是对外承诺，不是实现细节，需要有权限的人**明确决定**，不接受"评审没反对"作为通过。
3. **发布**：单独批准。版本号 bump 随 PR 是机械动作，tag/publish 是另一件事。
4. 本快照无 `.git`：目标仓库与批准人需要人指定（见 D9）。

回滚：单 PR revert 即回到 0.3.0 的行为与版本号；无数据迁移、无持久化格式、无外部副作用；唯一残留是"消费者已经看到过 `--json`"这类认知层面影响，代码层没有不可逆项。

## 6. 我对本计划最没把握的地方

D1（JSON 形状）。它是唯一一个"正确答案取决于我们看不见的消费者"的决定：`FEATURE.md` 只写"扩展名 → 行数"，仓库里没有任何下游脚本、issue 或消费者样例可以反推形状；而它一旦发布，改动成本最高。其余部分的不确定性都可以靠"多跑一次检查"消除，这一项不行——只能靠人拍板或补一个真实消费者用例。
