# 常驻规则与分层

读它的时候：要决定一条规则该写在哪一层、常驻文件太长、要写一条新的常驻规则，或要判断某个事实的权威归属。

## 层级表

| 层 | 它的工作 | 不属于它 |
|---|---|---|
| 根常驻文件 | 每个会话都需要的规则，每条 1–3 行并链接其家 | 故事、示例、情境流程、复述 |
| 子树常驻文件 | 该子树特有的命令 | 根文件已承载的全仓库规则 |
| 架构地图 | 模块、主流程、扩展点；改核心代码前必读 | 类型形状、单模块细节、决策理由 |
| 类型与接口目录 | 骨干词汇的字面形状与语义 | 行为叙述 |
| 决策记录 | 决策与理由，受自己的生命周期契约管辖 | 迁移计划、已完成的验收清单 |
| 事故复盘 | 事故故事；唯一允许战斗故事叙事的层 | 通用编码风格 |
| 危险模式文档 | 按危险领域分类的缺陷类规则，每条来自真实发生过或差点发生的缺陷 | 单次事故经过 |
| 菜谱 | 「怎么新增一个 X」的编号步骤与结尾验证命令 | 设计理由 |
| 模块 README | 该模块的配置、语义、已知限制、扩展点 | 复述 API 注释、别的模块的事 |
| 贡献者指南 | 环境搭建、日常流程、CI 形态概要 | 运行时理由、会漂移的门禁清单 |
| 生成目录 | 从源码再生成的穷尽枚举，由新鲜度门禁守护 | 任何手改 |
| 用户文档 | 面向产品用户的指南 | 生成的参考表、贡献者流程、决策史 |

## 归属判定顺序

1. 先定位这个事实在树上被谁拥有（它的主题归谁）。
2. 再定它允许的细节深度：描述自己的主题可以详尽；描述直接子节点只写用途、职责、高层行为；更低层细节链接到拥有它的后代。
3. 最后定它是教程还是参考。

文档类型不扩大它的范围：一份参考可以对自己的主题穷尽，不能顺手把子节点的细节也写完。测试机制、固定数据与脚手架属于最低的拥有层，上层只链接。

## 可移植的约定候选

常驻层放什么由项目决定。下列约定跨语言、跨领域成立，实践中反复证明值得占据常驻层的位置。逐条评估，不适用的删掉，不要照单全收。

- 随部署环境变化的选择必须是经校验的配置字段，不是常量或测试钩子；协议常量、外部规范、安全不变量保持固定。
- 配置错误要响亮地失败：能自包含判定的在加载时失败，否则在最早可判定处失败；绝不静默跳过缺失的引用目标。
- 默认值的解析是边界上一个显式的步骤，不是执行路径深处一个隐藏的「取不到就用这个」。请求进来先解析成完整规格，再执行。
- 空的异常捕获必须写明它吞掉了什么、为什么不会有别的东西到达这里，且 `try` 只包一条语句。
- 优先用维护良好的依赖而不是自己手搓，判据是它真的删掉了自己拥有的代码与测试、依赖本身健康、在边界上契合。为省一个小函数引入一棵依赖树是净损失。
- 并列的值优先保持对称；没有解释的不对称通常意味着漏掉了一次抽象。
- 运行时不变量断言的是自己拥有的动态关系（权威事件流、可变状态随时间的演化），不是「某个服务或方法存在」这类静态存在性检查。
- 封闭的枚举与联合要穷尽处理（能编译期检查的就编译期检查，否则显式默认分支抛错）；开放可扩展的必须有一个被文档化的默认分支。
- 跨边界的不透明标识符用具名类型包裹，不用裸字符串。
- 在类型与契约已经保证的同进程边界上信任它，不重复加运行时校验；校验只放在真正的信任边界：解析与配置、外部输入、持久化与文件、进程与线程边界、网络与协议。

语言与框架特有的约定（构建平面划分、模块系统细节、框架生命周期）属于项目自己的常驻层。

## 教程与参考分离

每份文档明确是教程还是参考。

- 教程沿一条有序路径通向一个结果，每步只引入这一步需要的东西。写之前先私下给读者起点知识与每个概念分级，先建立前提再引入依赖它的概念。
- 参考定义一个查询范围，描述当前行为，不依赖任何教学顺序。

两者内容都可观时必须分开；一侧很小时用清晰的结构边界隔开。混在一起的后果是两类读者都读不下去。

## 字数预算的机制

给每份长期文档设字数上限，写进一份清单，由门禁校验超限与文件缺失两个方向。红了按顺序：搬迁 → 压缩 → 抬阈值（附理由）。

三条纪律：

- 上限是护栏不是缩减目标。在目标以下时保留至少 5% 余量；超过目标时冻结上限，直到压回目标以下。
- 过低的上限是预算 bug，不是文档的错。内容确实需要空间时就抬阈值——因为上限太低而删掉真实契约是最坏的结果。
- 只在契约确实还有余地时才下调上限。

## 编辑常驻文件

- 文件被别的路径软链或镜像时，编辑真实文件，不编辑镜像。
- 每条规则保持自包含，同时链接高层文档。
- 能在保住清晰度的前提下压缩就压缩；确实需要更多空间时才抬上限。
- 改规则本身要有决策记录说明为什么；纯措辞修正不需要。
