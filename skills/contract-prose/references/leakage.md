# 泄漏与保留

读它的时候：在清理一段读起来像推导过程的文字，或要判断某个引用该删还是该留。

## 一个测试

对每段可疑文字问：**一个站在当前版本、没有会话记录、PR 线程与未提交草稿的读者，能否解析每一个引用并验证每一条断言？**

不能：把仍然成立的事实改写从现在可读的形态，删掉其余。
能：它不是泄漏，无论它读起来多像历史——但在当前态载体（README、文档、接口注释）上，一段可解析的变更故事仍然是变更叙述，要挪到它该在的地方。

## 八类形态与处理

1. **已失效的设计会期引用**：`(decision 7)`、`(audit C2)`、`design §4.7`、`plan §1.4`、`T4`、`W3`、`P-I` 这类阶段标签、「设计台账」。有已提交的归属就按名字与路径引用，否则删引用并把事实改写成独立成立。
2. **栈与 PR 视角**：「这个栈里后面的 PR」「本 PR 增加」「上一个提交」。改成已发布的机制或扩展点；延期的工作挪到一个待办标记或 issue 引用。
3. **变更叙述与版本印花**：「used to」「不再」「旧的 X」，以及「v1」「这一版」「今天」这类与过去对比的指示词。写现在的行为；一条已经修掉的回归写成现在时的反事实（「没有 X 时会发生 Y」），不写成仓库历史。
4. **评审编排**：「评审中否决了」「评审者确认」「这份笔记的第 5 稿」、轮次归属。留决定与理由作为普通事实，删掉谁在什么时候说的。
5. **对评审者的辩解**：「这个转换是安全的——只是……」「这是正确的，因为……」。注释在跟评审者辩护，而不是跟维护者交代。改成让它安全的不变量，或删掉。
6. **复述与推导转录**：控制流叙述（「先做 X 再做 Y」）、测试走查、显然分支的证明。删掉；只留非显然的契约或不变量。
7. **对冲与规划残留**：「目前大概可以」「应该够了」、没有标记的延期。提升为待办或改写成实际边界，删掉对冲。
8. **撰写语言残留**：正文语言里混进的未翻译片段、草稿分隔符。

## 明确保留

未经辅助的删除会双向失败：既删掉耐久引用，也留下死引用。下列按原样保留：

- **issue 引用**：`#1470`、`TODO(name):`、「issue #N owns the follow-up」在当前版本可解析，任何载体上都保留，包括 README。
- **已合并 PR 与 issue 引用，出现在决策记录与事故复盘中**：那是被认可的变更故事载体。
- **抑制理由**：lint 禁用理由、覆盖率忽略理由、空捕获说明——这是被要求的散文。理由错了就修正，不要删掉。
- **反事实回归钉**：「没有 X 就会 Y」「一个朴素的 X 会……」。
- **实测边界**：「实测：512 层约 0.15 秒」，其中「实测」是承重词。
- **运行时的新旧状态**：「旧连接排空之后新连接才接受」是运行时生命周期，不是变更史。
- **外部引用**：标准章节号（RFC 9110 §10.1.5）、设计稿名称；它们按设计在仓库外解析。
- **项目口吻的「我们」**，以及决策记录的备选段。

## 过度修剪的四种翻车

删之前逐项检查：

1. **把义务删成背书**：删掉「必须」「不得」之后，句子变成了对现状的赞许。
2. **把假设升格为已发布**：把「如果将来 X」改写成「X 已经……」。
3. **删掉真实事实**：为了让句子更短而丢掉一条约束。
4. **丢掉证据来源**：删了「实测」「依据 2026-08-12 的事故」，数字就失去可信度。

## 修的顺序

1. 先确认范围与排除项。范围没给就问，不要自己扩大成全仓。
2. 只读审计：先用特征探针扫可疑处（记得包含隐藏目录），每个探针先对一个已知正例与一个近似负例校准，再信它的输出；然后人工读密度最高的几处文字。
3. 按载体修：生成目录先找所有消费者，改源注释或模板，再重新生成派生物；双语文档先改一侧再最小改另一侧并重新记录配对；模型或用户可见的字符串要走行为证据，否则只报告不改。
4. 删之前数命题，过一遍上面的四种翻车。
5. 复查：只应剩下被认可保留的项；每个剩余引用在当前版本可解析；跑受影响载体的检查。
