# 变更传播细则

读它的时候：本次输入会改变已承诺的范围、关键约束、共享基线、优先级或完成条件，或者你在处理连续插单。

## 影响分析的五个面

在说「做不了」或「可以做」之前，先给出这五项，缺哪项就说哪项不清楚：

| 面 | 要说清什么 |
|---|---|
| 承诺 | 哪一项被增加、替换、延期或取消；与当前目标是否一致 |
| 契约 | 受影响的接口、数据、配置、持久化格式与它们的消费者 |
| 已有成果 | 哪些保留、哪些需调整；哪些验证仍有效、哪些待重验 |
| 依赖 | 受阻的先行工作、关键路径、外部承诺 |
| 风险 | 新增或改变的风险，以及谁承担后果 |

不无依据地报精确工期。

## 六步传播

1. 保存原承诺与改变原因。原目标被取消，不能写成已完成。
2. 为相关需求、验收条件、接口与决定形成**新的有效基线**。同一个适用范围不能同时存在互相矛盾的现行规则；不确定的话，先保留候选并标明它还不是现行。
3. 通知受影响的工作者新的基线与处置：继续、局部重做、等待、暂停、取消。不要无差别暂停整个项目。
4. 标明证据的复核范围。不是全量清零，也不是因为「之前通过」就永久有效。
5. 更新活跃工作、依赖、风险与下一步；对暂停的工作保存恢复点。
6. 在有意义的变更点保存版本锚点；过渡状态显式标记，不同步完成时不要宣称新基线已全体就绪。

小变更可以在当前任务里闭环，不必造独立文档；重大或跨工作流的变更留一条可引用的变更条目。

## 连续插单

多次插单时评估**净范围**，而不是逐条评估：

- 本轮承诺是否还能闭环？被挤出的是哪些？
- 在制工作是否过多？验收对象是否还在移动？
- 原交付条件是否已经不成立？如果不成立，记录必须反映这一点，而不是继续沿用旧口径。

主动报告并建议收敛：吸收哪几项、推后哪几项、本轮放弃哪几项。用户可以继续选择扩范围，但决定要留下记录。

## 什么时候重评而不是重问

已明确表达的处置不重复请示。只有出现下列情况才重新判断：

- 授权不再覆盖当前候选或环境；
- 出现新的安全、数据、费用或兼容边界；
- 用户撤回或替代了原决定；
- 关键未知被证伪，原方案的前提消失。

## 与验收的关系

范围变更后，原先的验收结论只覆盖旧候选。候选改变、集成方式改变或基线前进时，重算覆盖范围，并明确哪些结论可以复用、哪些必须重做。不能把「旧候选验收通过」当成「新候选也已验收」。
