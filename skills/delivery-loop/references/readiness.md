# 工程准备：当期能力与自证

读它的时候：一轮工作即将开始而构建、验证、隔离、持续检查或交付入口还不确定可用；或验收发现门禁、环境、替身与数据不可信。

## 只补当期缺口

工程准备不是一次性重建全部基建。按本次交付的真实执行方式判断需要什么，优先复用已有配置与仍然有效的证据。

| 能力 | 要确认的事实 |
|---|---|
| 构建与制品 | 依赖、构建入口与可识别产物可用 |
| 验证与数据 | 测试驱动、数据、环境与结果采集可用 |
| 隔离与依赖 | 并行工作、替身与真实依赖、敏感数据有边界 |
| 持续检查 | 当前需要的检查能运行并反馈 |
| 交付与恢复 | 当期需要的安装、部署、观察与恢复路径可验证 |

只补当前缺口。不为不存在的模块、未来风险或「体系完整性」搭平台——空壳检查永远不会失败，只会训练所有人忽略它。

## 能力要能辨别对错

新增或实质改变的关键能力，要给出有针对性的正向与反向证据，而不是只证明进程能启动：

- 关键门禁对受控坏样例确实失败或阻断，而不是忽略失败时返回的退出码。
- 替身与共享契约一致；采集结果反映真实执行，而不是空报告或错误统计。
- 构建、环境与交付入口对当期代表对象可用；恢复路径按风险验证过。
- 受控坏样例不进实际交付，也不为验证门禁去影响生产。

## 入口要能被别人找到

维护必要配置、环境与验证说明，使执行者能找到可运行入口、限制与负责人。

能力不能只存在于本会话或个人机器的隐式状态里：换一台机器、换一个会话，它应当仍然可运行，或至少缺口被写明。

## 边界

- 付费、配额、生产数据与破坏性外部调用要有授权与隔离边界。
- 高频验证用替身，真实依赖做有界核验；替身通过不能证明真实服务可用。
- 实验代码与占位用例不能冒充完整验收；它们证明的是能力，不是业务结果。

## 缺口怎么记

缺口不被模板或占位配置掩盖。每一项写成：缺什么、挡住哪项工作、谁负责补、补上之前哪些声明不成立。

局部准备成功不等于全部未来基建就绪；后续范围仍有缺口时，它不阻塞无关的就绪工作。
