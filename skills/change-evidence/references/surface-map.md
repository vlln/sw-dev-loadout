# 触达面到证据

读它的时候：改动横跨多个层、你说不清它到底触达了什么，或要为一个不常见的改动面（数据、配置、权限、错误路径）选证据。

## 枚举表面

从 diff 反推，而不是从模块名反推。逐条问：

1. 这个改动让哪个外部可观察的东西不同了？（返回值、输出、持久化、事件、副作用、时序、错误）
2. 谁观察到它？进程内的调用者、另一个进程、模型、用户、外部消费者。
3. 这个观察是经过编译、打包还是部署才成立的？
4. 它依赖哪些不由本仓库拥有的东西？（网络、时钟、随机、外部服务、操作系统）

四个答案拼起来就是表面。表面决定证据；模块名不决定。

## 判据：什么算「同一表面」

同一表面意味着：一处行为改变会让另一处的观察结果也改变。反过来，共享一个文件、共享一个包、共享一个测试文件都不构成同一表面。

## 常见易漏的表面

| 改动 | 容易漏掉的触达 |
|---|---|
| 改默认值 | 所有依赖该默认值但没显式传参的调用路径；文档里的默认值；迁移前的数据 |
| 改错误信息 | 解析错误信息的调用者、日志告警的关键词匹配、本地化字典 |
| 改权限判断 | 拒绝路径（不只是允许路径）、缓存过的判定结果、批量操作 |
| 改序列化格式 | 旧数据的读取、跨版本兼容、外部消费者、固定数据 |
| 改排序或去重 | 依赖稳定顺序的下游、分页边界、快照 |
| 改并发结构 | 取消路径、拆卸、错误归属、超时预算 |
| 改配置键名 | 部署配置、示例配置、文档、环境变量映射 |
| 改公开导出 | 类型声明、构建产物、外部消费者、清单文件 |
| 改依赖版本 | 传递依赖、平台构建、锁文件、体积或启动时间 |

## 跨多个表面时

一个改动同时触达三个表面时，不要求跑三套全量证据，而是：

1. 每个表面选它最窄的那条证据。
2. 「最窄」以「会不会因为这条回归失败」判，不以「跑得少」判。
3. 能用一个更宽的检查一次覆盖多个表面时，比较两者的成本与信噪比，选一个，别两个都跑。
4. 表面上没有可用证据时，这是缺口：要么补一条，要么明确写下「无覆盖 + 风险 + 谁接受」。

## 不确定时的默认

按这个顺序退让，直到找到能跑的东西：

1. 拥有该行为的测试，按用例名过滤。
2. 拥有该行为的测试文件全跑。
3. 相邻包的测试（共享契约变了时）。
4. 该层的完整 job（本地只在该改动确实横跨全仓时）。
5. 全量预演（只在明确要求、诊断 CI 失败、或改动不可约简地遍及全仓库时）。

退到第 4 步时，写下退让的理由。没有理由的退让就是「不知道该跑什么」的伪装。

## 证据与声明的对应

一条证据只能支撑它实际覆盖的声明：

- 单元测试绿 → 不能说「部署后可用了」。
- 快照绿 → 不能说「外部消费者兼容」。
- 本地绿 → 不能说「平台矩阵通过」。
- 分支绿 → 不能说「集成候选通过」。

写完成声明时，逐句问：这句话覆盖的范围，有没有一条跑过的证据对应它。
