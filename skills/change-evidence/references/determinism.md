# 确定性测试

读它的时候：在写涉及端口、临时目录、时钟、子进程、并发或拆卸的测试，或在调查一次偶发失败。

## 模型：假设这些层会重叠

除非当前配置证明不是，否则假设下列层可以重叠：

1. 同一文件里的用例。
2. 不同文件或不同 worker 进程。
3. 同一 job 里独立的测试进程或仓库门禁进程。
4. 共享同一台宿主机的不同 CI job。

进程隔离**不**隔离宿主端口、可预测的文件系统路径、外部服务、数据库、套接字与继承来的子进程。

对每个取得的资源，能说出：所有者、原子分配方式、可观察的就绪信号、已注册的清理、静止完成信号。五样缺一样，这个资源就是偶发失败的来源。

不要因为一个固定数据缺隔离就把整个套件串行：先缩窄独占范围或改资源分配方式。一个串行的用例块保护不了宿主资源不受另一个文件、进程、job 或 runner 影响。

## 原子分配

- 网络：绑定回环的 0 端口，在服务报告已监听之后再读分配到的地址。绝不先探测空闲端口再晚些绑定。
- 文件：用私有随机临时根；不取得可预测的共享路径；必须独占时用排他创建。
- 数据库、套接字、会话、输出位置：每测试唯一命名空间。
- 稳定的录制标识与短暂的传输地址分开：在固定数据内部做转换，不要为了迁就录制值去改真实资源。

只作为解析输入或期望值出现的字面路径与 URL 不是取得的资源，不要因为「看起来固定」就去改它们。

## 进程全局状态

独占可变资源清单：环境变量、工作目录、假时钟、区域与时区、模块 mock、注册表、控制台钩子、全局 this、全局 fetch 拦截。

优先级：注入依赖或实例级适配 > 局部修改 > 全局修改。

必须改时：

1. 记录原值是「不存在」还是「存在」。
2. 恢复那个确切状态（恢复成 undefined 与删除键不是一回事）。
3. 取得后立刻注册恢复。
4. 用 `try/finally` 包住最小作用域。
5. 保留一个兜底钩子，覆盖「失败发生在局部 finally 之前」的情况。
6. 拦截最窄的那个确切请求或调用。

## 平台语义

同一个值经过操作系统往返，不一定原样返回：

- 写回一个值只有在断言容忍写回失败时才安全。依赖恢复的断言，期望值要从新读一次取得，不能用记忆中的值。
- 环境变量名在部分平台上大小写不敏感：同时设置两个只差大小写的键，在那里只有一个条目。
- 文件句柄的释放可能是异步的：在一种平台上立刻完成的改名或删除，在另一种平台需要按实测竞争定一个上界重试。
- 权限与信号语义并非所有平台都有：依赖它们时用带原因的显式平台跳过，而不是在所有平台上削弱断言。

优先选在所有平台都成立的观察。

## 超时预算

用例级或块级超时是**覆盖**运行器的默认值，不是顺从它。低于所在 lane 预算的字面值，实际是在收紧 CI 已经给的时间；同一个字面值在默认更小的主机上读起来却是放宽。

- 受进程创建约束的套件取 lane 的预算；更紧的值要写明为什么更紧。
- 加用例预算时要一起加钩子预算：准备与拆卸付同样的竞争成本，只抬用例预算会把争用失败推到拆卸里。
- 当被测对象就是超时时，外层等待要远大于被测超时，否则负载会决定哪一侧先超时。

## 同步

- 等显式就绪事件、握手、状态转换、自己拥有的 promise，或外部可观察条件。
- 用受控 promise 或屏障把竞态放到确定的位置，并证明相关操作确实重叠。
- 超时只用来给等待设上界，绝不用来做断言成立的条件。
- 不断言依赖调度顺序的行为，除非该顺序就是被测的产品行为。
- 时间本身是被测对象时，注入或伪造时钟，并总是恢复真实计时器。

## 拆卸到静止

取得资源后立刻注册清理，让断言失败也释放资源。

清理要做完：停止新的回调或请求、摘掉监听、恢复全局钩子、终止自己拥有的工作，并等待子进程退出、服务关闭、worker 终止或等价完成信号。

只调用 `abort()`、`close()` 或 `kill()` 而不等完成信号，是不完整的拆卸。存在晚到完成的可能时，证明拆卸确实阻止了它去改另一个测试的状态。

## 诊断一次偶发失败

1. 记录确切命令、失败用例与平台差异。
2. 先判断它是真缺陷、测试隔离问题，还是环境问题；给出依据。
3. 检查上面五要素里缺哪一样（所有者、分配、就绪、清理、静止）。
4. 用屏障或并发进程复现，而不是重复跑碰运气。
5. 修根因；把「加超时、加重试、串行化、吞错、弱化断言」留作最后手段，且必须写明它换掉了哪个待等状态。

## 拒绝掩蔽

可以接受的两类「看起来像掩蔽」：

- 把预算恢复到所在 lane 本来就给的额度。
- 按实测竞争把有界重试定到观察到的量级。

两者都命名了在等的工作。其余「让它变绿」的手段都不算修复。
