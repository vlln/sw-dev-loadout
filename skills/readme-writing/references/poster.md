## 观察和规则必须分开

S01 用居中 hero 容器但没有标准一级标题；S06 顶部含多排社会证明；S07 是 Quick Start 在视频之前；S12 是徽章在 logo 之前。它们并不一致采用下列完整链条。

**本 skill 的海报式约定**：可选首图 → 居中标题 / 定位 → 独立语言 / 外链 / 导航行（按需）→ 精选徽章 → 功能展示 → 安装 / 使用 → 信任与FAQ（按需）→ 开发者入口 → License。

展示优先与清晰的视觉层级是核心；左右交替、图文表和节间 `<br>` 是可借用的呈现手段，不是每个项目必须照搬的布局。首图、语言版本与 emoji 按内容和偏好选择。完整语法见 `$_S/references/visual-cookbook.md`。

## 首屏：从真实部件组装

### hero：先给读者一个可识别的东西

S01 使用 logo，S06 用随深浅色切换的品牌图，S07 也提供两种背景入口。迁移时选择真正属于目标项目的主视觉：界面概览、演示关键帧、项目专属横幅或字标。

- 首图可选：logo、产品图、横幅、演示关键帧均可；使用时置于顶部居中，标题在其后。
- alt 说明产品与图中内容；图片不是定位句的替代物。
- 有深浅版 logo / banner 时配对；其他图在另一背景不清晰时也配对。
- 没有合适素材可直接省略首图，不强制创作、不填无关图或假界面。省略首图不等于省略后续真实能力展示。

### 标题、定位与入口

默认专业简洁，操作指令式；友好语气仅在任务明确要求时采用，不与海报式视觉绑定。具体语言检查见 `$_S/references/language.md`。

标题居中，定位句用具体能力与适用对象说明是什么。标题优先准确的任务 / 内容名，不为亲切刻意拉长。短品牌语可以辅助，但不能代替定义或在正文反复出现。

S07 的家族口号不等于本仓库支持所有云；迁移时主张与当前项目范围必须一致。S06 首屏定位与 Quick Start 面向的目标应用出现偏移，不能照搬这种入口漂移。

精选导航借 S12 的主/次 CTA 层级：一个主要开始入口，再给真实演示、文档或反馈；只保留读者会点击的几个。没有在线演示就删该链接，不编一个网址；导航仍需成立。

徽章参考 S01/S06 的统一样式，但本 skill 收敛为 1–3 枚、最多5枚。版本、许可、CI或支持面有可验证来源才展示；合作标识不能擅自改称“客户”。

## Markdown 与呈现选项

- 多语言切换独立一行；产品站 / 文档等外链可另成一行，站内导航与徽章不挤在同一排。只放已有语言版本与真实入口。
- 步骤存在先后依赖时用序号，不为并列能力制造编号；相同类型有共同字段时优先表格，如平台 / 安装方式、能力 / 依赖 / 降级。无字段可比的短项仍用列表。
- emoji 可启用或禁用，按任务明确的偏好；未指定则沿用项目惯例，否则默认不用。启用时一节至多一个语义明确的图标，不替代标题文字；同步检查锚点。
- `NOTE` 补充必要事实，`TIP` 给可选捷径，`IMPORTANT` 标不可忽略的前提，`WARNING` / `CAUTION` 提示具体风险；不是每节都要放。GitHub alerts 在不支持该扩展的渲染平台改为普通引用块加粗标签。
- 标题和章节划分均可调整：演示区按具体任务命名或并入功能展示；比较区无必要就删除；依赖 / 费用 / 隐私可拆分、改名或删除不适用项。不是必须出现“看它完成一次任务”“使用前后”“费用、账号与数据”这三个节。保持展示先于使用、必要决策信息不丢、许可收尾，并同步导航。
- 模板应直接示范该语义：演示与安装用有序步骤（命令嵌入相应步骤），多种安装方式、同类依赖与参与入口用字段一致的表格。不能只在 reference 写规则而让 template 继续平铺同类段落。

## 展示：给“产出证据”，不是视觉堆叠

### 先展示一个完整结果

S01 在安装前给 walkthrough、三个具体输出和 Before vs. After；这说明演示应能回答“用了之后到底得到什么”。

目标项目选择最短可理解的真实任务：输入是什么、执行了什么、结果是什么。使用视频要在前后写文字说明，并给播放器失效时的真实备用入口；不继承“零延迟”等未核实承诺。

CLI 可借 S08 的 GIF 或真实命令输出，不强行做假 GUI。演示只有按钮或空仪表盘、看不出结果时，不算有效展示。

### 根据内容设计展示，不固定套布局

先确定读者最值得看到的结果，再决定载体与组织方式。截图、运行片段、实际产物、案例对照、语义图和精编内容片段都可使用；不把 GUI 截图逻辑套给所有项目，也不为不同项目类别预设唯一替代格式。

展示单元应让读者迅速看见任务、成果与必要边界。图文并列、左右交替是模板提供的一种示范，可改为宽幅图、紧凑对照、短案例或其他适合内容的组织；不要求一个功能对应一张图或一个二级标题。

### 主动准备素材

1. 盘点真实内容和可用资源，判断哪些能直接解释价值，而非只证明作者写过规则。
2. 缺少现成素材时自行完成：截取界面、运行获准的最小任务、制作语义图、排版实际产物或设计项目视觉。可组合工具，不把可自行完成的素材准备默认转为询问。
3. 检查文字是否可读、信息是否准确、深浅背景是否可用，修正后再嵌入。新增素材与 README 一起交付，保留可编辑来源或重建方法。
4. 创作示意用准确短标签说明性质，例如“案例示意，非运行记录”；不伪造使用者评价、运行结果、指标或界面。标注一次即可，不在图片、图注和正文重复列否定声明。

没有现成截图不构成停止理由；主动选取或制作合适的表达。不可执行的敏感 / 外部操作遵守授权边界，并继续用获准方式完成其余展示，不以缺素材退回标准式。

### 对比只比较读者关心的改变

S01 的 Before vs. After 和 S08 的“任务 / 工具命令 / 原生git”可归纳为：旧流程哪里费力，新流程省掉什么，代价是什么。

不要照搬第三方产品的负面结论、绝对性能或生命周期声明。S07 的兼容表会标 stub/mock 等具体边界，值得借鉴“能力伴随限制”，但不能从“有此API”推断完整实现。

## 使用：从展示平滑走到第一步

展示之后给主安装 / 访问入口。借 S07/S08 的主次路径分层：推荐方式直接可见，其他平台与高级部署折叠或链接出去。

安装必须包含必要前提、真实命令、成功反馈和第一项可完成任务。包安装、目标应用中的注册、激活和重启不是同一件事；按目标项目实际关系解释。

不要把截图里的版本、地址、包名当作当前目标的事实。演示中的外部服务若收费、上传数据或要求账号，在读者触发前说清楚。

## 信任：让人敢用、敢退出

S06 的隐私选择说明和 S07 的本地 / 服务边界启发如下问题；各答案必须从目标项目取证，而不是继承其承诺：

| 问题 | 应写到的具体程度 |
|---|---|
| 是否收费 | 哪部分收费、由谁计费，不只写“免费” |
| 哪些外部依赖 | 文本模型、图像服务、账号分别做什么 |
| 不配置会怎样 | 写具体降级行为，不笼统写“不可用” |
| 数据去哪里 | 使用者本地存储与外部调用分开说明 |
| 能否卸载 | 真实卸载入口，项目数据是否保留 |
| 凭什么信任 | 可核实维护者、许可与安全入口，不伪造背书 |

仅保留影响目标读者决策的项目，不为凑齐本表增加费用、权限或隐私免责声明。同一事实集中说一次；具体风险放相关操作前。

## FAQ、开发入口与结束

FAQ 按目标读者的实际问题提问，答案短、可验证；次要详情可以折叠。核心安装、价值定位和许可不折叠。

架构、开发、测试细节可给短入口，不让它们吞没产品首页。不要把 S01 的全部开发指南或 S07 的全部服务表原样搬进来。

License 放最后是本 skill 约定；来源 S01/S06 的许可后还有追加内容，不将其当成最佳顺序照搬。

## 验收

读者先看见价值与具体成果，再进入安装；版式由内容驱动，有清晰焦点与视觉节奏，而不是标准说明文加居中标题。素材已主动准备、检查并随文交付，示意与实测区分；首图可选，不要求固定截图数量或左右交替。序号、同类表格、提示块和导航符合语义；正文与媒体文案每句有信息增量，图表和正文不重复复述，必要边界不扩散为反复辩护；事实可核。
