# 语气与信息密度

**何时读**：选择语气、填充模板后精简初稿、审查正文或图片文案时。适用于全部风格，不改变各自的视觉布局与必要信息。

## 默认与覆盖

默认专业简洁：说明事实，操作用指令式，收益落实到具体动作与产物。海报式可以视觉鲜明而语言克制，不要求宣传腔、抽象口号或对读者说教。

任务要求友好语气时，用熟悉的词、必要的解释与自然句式降低理解成本，而不是增加“先来看看”“你还需要知道”“不只是……更是……”等铺垫。短口号仅在有独立品牌作用时保留，不能代替定义或在正文反复变体出现。

## 信息增量判据

一句话至少提供以下一种信息：能力、适用对象、输入输出、操作、必要条件、限制、可核实证据或有效入口。删掉后不影响判断或操作的句子，删除或合并。

“专业简洁”不是所有句子都越短越好，也不是删除解释。新概念、关键前提、风险与研究局限需要说清；完整例子可以较长，但每段应承担不同职责。不用字符数或压缩比例代替判断。

## 写法对照

以下是编辑示例，不是对任何项目事实的声明。精简版只在目标项目确实满足其前提时使用。

| 低信息密度写法 | 更直接的写法 | 修正点 |
|---|---|---|
| 先试读，不改环境。打开对应入口，让 Agent 阅读正文，再提出你的真实问题。 | 无需安装：让 Agent 读取对应的 `SKILL.md`，再提交任务。 | 直接给前提与动作 |
| 把“改好了”变成有契约、有证据、能接手的成果。 | 提供行为契约、验证范围和交接记录的编写规则。 | 用能力与产物替代口号 |
| 按眼前的任务选 | 技能 | 导航标题不靠修辞拉长 |
| 从一个真实问题开始 | 用法 | 用常见名称指明内容 |
| 用之前知道这些 | 限制 | 直接命名信息类别 |
| 不必先采用整套流程，找到眼前的问题，从对应技能开始，跨到其他问题时再组合。 | 各技能可独立使用或组合。 | 合并重复的使用原则 |
| 这些技能提供工作方法，不冒充执行结果；检查要实际运行，放行仍需依据与授权。 | 技能提供操作规范；执行与外部操作由所用 Agent 的执行工具完成。 | 去掉辩护；具体授权要求留在相关步骤 |
| 这是原创案例，不是运行截图，不是实际日志，也不代表功能已经实现或验证。 | 案例示意，非运行记录。 | 用准确短标签界定证据性质 |

## 跨媒介去重

- 图片展示具体结果，图注补充必要上下文或证据性质；正文解释读者下一步需要的信息，不逐行复述图片。
- 表格应补比较维度或帮助选择；若只是把上一段换行重排，保留一种表达。
- 同一边界集中说明一次。仅当某一步存在不同风险或读者可能跳读而误操作时，在该步骤前保留必要提醒。
- NOTE 等块不能成为重复免责声明容器。清楚标示“示意”不需要再连续列出多种否定。
- 测试未执行等编写过程放交付说明；目标读者使用前必须知道的兼容性与限制仍留正文，不能借“过程隔离”隐藏。

## 交付前减法

1. 标出每段新增的事实或动作；没有新增内容的段落删掉。
2. 对照图片、图注、表格和提示块，合并同义复述。
3. 将抽象收益改为可核实能力 / 结果；没有事实支持的主张删掉。
4. 核对标题能否直接说明内容；普通名称更准确时不要刻意改写成问句或口号。
5. 复查删减后是否丢失前提、风险、限制、来源与成功信号；有则补回最短必要表述。

验收不是“语气标签已填写”，而是正文与媒体文案实际满足以上判据。审查发现给原句、改法与保留信息，不只写“可以更简洁”。
