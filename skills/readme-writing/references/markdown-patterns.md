# Markdown 呈现模式

**何时读**：组织步骤、同类信息、提示块或 emoji；调整模板标题与导航时。下列是语法示例，不是必须全部加入的区块。

## 步骤和同类信息

有先后依赖的操作用有序列表；没有先后关系的能力用无序列表。多项同类对象具有共同字段时优先表格，如平台 / 安装命令 / 限制、能力 / 依赖 / 降级行为。没有比较维度的短句不硬做表格。

```markdown
1. 准备输入。
2. 执行主任务。
3. 检查输出与成功信号。

| 能力 | 需要什么 | 不配置会怎样 |
|---|---|---|
| {{能力}} | {{依赖}} | {{具体降级行为}} |
```

## GitHub 提示块

GitHub alerts 是GitHub 特有扩展，不是所有 Markdown 渲染器都支持。用于一条重要事实，不代替正文；每块只讲一件事，避免连续堆叠。非 GitHub 渲染平台先核支持情况，不支持时用普通引用块。

```markdown
> [!NOTE]
> {{影响理解的补充事实。}}

> [!TIP]
> {{可选的便捷做法，不是主路径前提。}}

> [!IMPORTANT]
> {{继续操作前必须满足的条件。}}

> [!WARNING]
> {{潜在损失、数据外发或其他风险及规避办法。}}

> [!CAUTION]
> {{可能造成不可逆后果的具体操作及必要确认。}}
```

降级写法：

```markdown
> **注意：** {{补充事实。}}
```

平台语法依据：[GitHub Docs — Alerts](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/basic-writing-and-formatting-syntax#alerts)。类型由语义选择，不把风险提示当装饰，不为了补齐五种类型编造警告。

## emoji 与标题

emoji 开关独立于 README 风格。遵守任务明确的偏好；未指定时沿用项目已有惯例，否则默认不用。启用时少量、一致，一节至多一个明确图标；正文标题不能只剩图标。

“快速开始”“开始使用”“安装与运行”可以服务相同任务。标题的名称、语言和合并方式可以调整，内容职责与主顺序才是约束。改标题、加 emoji 后都要按目标渲染平台检查锚点，不能直接假设旧链接仍有效。

## 多语言与外链

```html
<p align="center">简体中文 · <a href="{{英文版本相对路径}}">English</a></p>

<p align="center"><a href="{{产品站地址}}">产品站</a> · <a href="{{外部文档地址}}">文档</a></p>
```

语言、外链与站内导航各成独立行，避免与徽章拥挤。不存在的版本不展示；语言版本保留相同事实，不能只生成切换链接而没有对应文件。
