# 写一份读者优先的 README

主要回答：**什么样的 README 对目标读者有用，怎样写得更好。** 合格线与写法分开判断；格式检查通过不等于信息与呈现合格。

## 事实：发布平台与来源

- README 的 Markdown / HTML 支持取决于发布平台，不能把 GitHub 专用布局直接当作包页面或纯文本环境的保证。
- [发布平台约束](references/publishing-platforms.md)。读它的时候：使用 GitHub HTML、提示块、自动目录或大媒体前；其中事实带来源和核对日期。
- [来源目录](references/source-catalog.md)。读它的时候：核对某种风格的归纳依据、精确借鉴真实布局或新增风格；样本自述不等于目标项目事实。

以下链接指向包内文件；`$_S` 在深读材料中表示本 skill 根目录，读取前解析为实际路径，不按目标项目的工作目录解释。

## 判据：合格线

**面向读者**

- 首屏说明是什么、给谁用；建议定位句不超过 120 字符，不用抽象赞美替代定义。
- 每节解决目标读者的一个问题，顺序按其决定与操作路径，不按源码模块。
- 安装前提、最小用例和成功信号明确；完整 API、实现清单与开发流水不占主路径，必要深文档留有效入口。
- 科研项目的论文、环境、数据、复现条件、结果出处和局限是主内容，不能当作工程流水账删掉。

**事实与证据**

- 能力、命令、输出、平台与许可来自项目或可核对材料，不从名称、机构或参考 README 推断。
- 实测、预期与创作示意明确区分，不编造运行记录、指标、引用、使用者评价或界面。
- 关键命令可复制，输入明确；付费、覆盖、删除、数据外发等必要前提在相应操作前说明，执行遵守授权范围。
- 链接与资源存在，图片和徽章有 alt；外部不可达项记未验证，不当作通过。
- 许可信息收尾，名称 / SPDX 与实际文件一致；代码、数据、权重等不同许可分别说明，未知不猜。

**表达与结构**

- 默认专业简洁，操作用指令式；视觉风格、语气、语言和 emoji 是独立维度。任务明确指定的要求优先，否则采用所选风格默认。
- 每句增加能力、输入输出、动作、条件或入口；无信息增量的铺垫、口号与说教删除。删掉一句后，目标读者既不会做错决定，也不会少一步关键操作，就删。
- 图片、图注、表格、正文和提示块不反复解释同一事实。示意性质就近短标，具体风险保留，不扩散成重复免责声明。
- 一个一级标题，层级不跳；代码块标语言，命令与输出分开。顺序操作用编号，同类信息有共同字段时优先表格。
- 模板标题和章节不是固定清单：可改名、合并、拆分或删除可选节；必要信息与主阅读顺序保留，改名同步导航与锚点。

## 写法：风格与默认值

任务未指定风格时，沿用合适现状，否则按主要读者任务选择；用途不明用极简作为保守默认。只有未知受众会实质改变结构时才问，不必逐项询问无关偏好。

| 风格 | 默认任务与语气 | 指南 | 实际模板 |
|---|---|---|---|
| 极简实用 | CLI、脚本、小库；短句指令式 | [minimal](references/minimal.md) | [模板](assets/minimal.template.md) |
| 标准开源完备 | 公共库、框架；专业克制 | [standard](references/standard.md) | [模板](assets/standard.template.md) |
| 海报式 | 重展示的产品或项目；专业简洁，具体结果 | [poster](references/poster.md) | [模板](assets/poster.template.md) |
| 学术科研 | 论文代码、实验复现；严谨客观，操作直接 | [research](references/research.md) | [模板](assets/research.template.md) |

上表的指南与模板只读取选中的一对。指南说明来源、取舍与验收；模板提供可填充的 README，不是描述性教程。混合项目保留一个主顺序，不拼接两套完整模板。

- [风格选择与文件路由](references/styles.md)。读它的时候：受众混合、覆盖默认语气、调整标题或判断模板区块是否适用。
- [语言与信息密度](references/language.md)。读它的时候：初稿完成后做语言减法，或审查正文与图片文案的冗余；友好语气仍受同样约束。

**海报式的关键取舍**

- 居中定位、入口分行，具体成果展示先于安装。首图可选；无图本身不是失败，教程提前也不等于成果展示。
- 按内容决定截图、实际产物、案例、语义图或精编片段及其布局，不固定要求一功能一图或左右交替，不只给标准说明文加居中标题。
- 素材准备属于写作：主动制作、截取或运行获准的最小例子，检查可读性后交付；不以没有现成素材为由退回其他风格。创作示意不得冒充实测。

**按规模裁剪**

局部修正保留有效现状，只检查受影响事实、链接与语言；全新或重写再选完整风格结构。短链工具超过约 150 行或 8 个二级标题时先查是否塞入深参考；这不是完备型、海报式或科研型的硬上限。明显偏离默认时，在交付说明写一句读者需要的理由，不把编辑过程写入正文。

## 易错点与按需材料

- 可选首图与展示素材是不同判断；首图可以不做，需要展示的内容应主动完成。
- 模板槽位不代表项目已有对应功能或文档；填入可核实事实，删除占位符、编辑注释与无依据的入口。
- 图文中的证据标签不能靠重复否定堆砌；精简不能删除操作风险或研究局限。
- [反模式与内容去处](references/anti-patterns.md)。读它的时候：审现有 README，或决定删什么、搬去哪。
- [视觉片段库](references/visual-cookbook.md)。读它的时候：制作图片、视频、图文单元或折叠区；布局片段不是唯一合法版式。
- [Markdown 呈现模式](references/markdown-patterns.md)。读它的时候：组织序号、表格、提示块、语言行或 emoji；目标渲染平台不支持时采用普通 Markdown 后路。
- [徽章来源](references/badges.md)。读它的时候：选择或修复徽章；默认 0–3 枚、最多 5 枚，海报式优先精选 1–3 枚且每枚有证据链接。

## 自检与修正

[自检的取证动作](references/self-check.md)。读它的时候：交付前检查或提供可复核审稿结论；按适用项执行，不全量套用无关检查。

1. 对照读者任务和选定风格，核对必要信息、呈现与默认值；发现缺口先修，不用标签代替实际判断。
2. 核对事实、命令、输入输出、链接和素材；区分通过 / 不通过 / 不适用，未验证单列。
3. 检查标题与导航、编号与表格、占位符、许可及语言密度；媒体存在还应实际查看，不只查路径。
4. 修正后重查受影响项。审稿给问题、位置、影响与最小修法；写作交付给产物、风格 / 语气和验证边界，不将过程说明塞进 README。

核对规则时应用反例：先安装后展示不满足海报式主顺序；把论文值写成复现值不满足证据要求；图注和正文逐句复述不满足信息增量。规则与检查应能指出这些错误，不能只报告文件格式正确。
